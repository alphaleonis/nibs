# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/),
and this project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **`nibs check` now reports two load-time problems it previously kept to itself.** An **unparseable nib file** is skipped at load, so the nib is absent from every query with nothing to explain why; a **duplicate id on disk** means one file silently shadows another, with the winner decided by load order. Both were detected all along and written only to stderr, which nothing redirects — so they were invisible in `--json`, in `nibs serve`, and in the TUI. They now appear in a `Nib Files` section (reported before `Nib Links`, since a skipped file is what makes links to it look broken) and in the `--json` envelope as `unparseable_files` and `duplicate_ids`. Neither is auto-fixable — repairing YAML means editing what you wrote, and resolving a duplicate means choosing which file to lose — so `--fix` reports them and says it cannot repair them rather than skipping them silently.
- **A GitHub-style query language in the web filter box.** The keyword box now accepts `field:value` tokens alongside bare-word full-text search: `type:bug status:todo` filters on both facets, `-tags:wip` negates, `status:todo,in-progress` is OR-within-a-field, and `status:open` / `status:closed` are group shorthands for the whole set. Space means AND across fields. The grammar is lenient in and canonical out — repeats, stray commas and any typing order are accepted, and the box rewrites itself to one canonical spelling on blur.
- **Relationship and hierarchy filtering from the box**, answering questions the dropdowns cannot: `parent:<id>`, `ancestor:<id>`, `descendant:<id>`, `sibling:<id>`, `blocking:<id>`, `blocked-by:<id>`, `mentions:<id>`, `mentioned-by:<id>`, plus the tri-state existence tokens `has:parent` / `no:parent`, `has:blocking` / `no:blocking`, `has:blocked-by` / `no:blocked-by` and `is:blocked`. Each name states the relationship the *matched* nib holds toward the given id, so `ancestor:X` selects X's descendants.
- **The filter box and the facet dropdowns stay in sync in both directions.** Typing a token ticks the matching dropdown as you type; toggling a dropdown rewrites the box text. The two surfaces can no longer disagree.
- **Filtered views are shareable.** The canonical query is mirrored into a `?q=` URL parameter, so any filter can be bookmarked or pasted to someone else. On load the URL wins over the stored preference. The filter preference is now persisted as that same query string rather than a structured blob; existing stored filters are read and translated automatically.
- **Syntax highlighting in the filter box**, colored per token: the field name and its punctuation read as structure, the value takes the accent and sits in a slightly recessed well, free text stays muted, and a value that is not legal for its field gets a red wavy underline. An invalid token is preserved rather than discarded — results reflect the valid part while the typo survives blur, a dropdown edit and a round-trip through the URL.
- **A `?` at the end of the filter band opens a syntax reference** for the whole query language — every field with its legal values, every relationship and presence token with a one-line description, the operators, and worked examples. The token tables are generated from the same vocabulary the parser reads, so the panel cannot document a token the box would reject or omit one it accepts.
- **Autocomplete for the whole query vocabulary** — field names, enum values, group names and existing tags. <kbd>Tab</kbd> accepts the active suggestion, <kbd>Ctrl</kbd>+<kbd>Space</kbd> opens the menu on demand, and relationship-token values offer an async id/title typeahead so a nib can be picked by name instead of by id.
- **"Filter related" on the row context menu** composes a relationship filter for the nib under the cursor — items blocking it, items it blocks, its children, its ancestors, its siblings, its mentions — without needing to know or type its id. The token is ANDed onto the current query rather than replacing it.
- **Clicking a token in the box selects it** for quick editing or deletion.
- **GraphQL `NibFilter` gains `ancestorId`, `descendantId` and `siblingId`** — subtree, ancestor-chain and sibling predicates, each excluding the target nib itself.
- **`nibs close --as <closed status>`** — closing is now one verb that produces any closed status. `nibs close <id> --summary -` still records `completed`; `--as scrapped` and `--as deferred` record the other reasons. `--as` takes ordinary status names, so there is no separate close-reason vocabulary to keep in sync, and an open status name is a validation error.
- **`## Summary` accrues instead of being replaced.** Each close appends a dated, reason-stamped entry (`**Deferred 2026-07-27** — waiting on the upstream release`), so a nib can be closed again to revise its reason without destroying the first rationale. Re-closing under the same reason is allowed too — that is how a rationale gets updated.
- **The tracking-nib pattern is documented** in `nibs prime` and `nibs prime --full`: when work waits on something outside the tracker, make a nib for the external event and `--blocked-by` it. `--blocked-by` takes ids only, because an external blocker needs a resolution event and only a nib can carry one.
- A guard test parses `web/src/lib/constants.ts` and pins its status names and closed set against the Go configuration, so the web's hand-written copy of the vocabulary can no longer drift unnoticed.
- **The GraphQL `Mutation` type now documents that a batch is not atomic.** Root mutation fields execute serially in document order, execution does not stop at the first failure, and each field commits on its own — so a response reporting failure can still have written durable edits. The type previously carried no documentation at all, leaving a caller composing a batch to discover this by experiment. This ratifies existing behavior rather than changing it, and points at `nibs prime --full` for the fuller treatment instead of duplicating it, so the two cannot drift apart.

### Changed
- **The web UI settled on one name per field.** The status facet, its column and its internal keys are all "Status" (previously "State" in places), and the estimate facet is "Estimate" (previously "Effort"). The words in the UI now match the words the query language and the CLI use.
- **The filter query box is wider**, and on narrow screens the facet dropdowns stack below it instead of squeezing it.
- `nibs serve` sends SPA cache headers, so a rebuilt UI is picked up instead of being served stale from the browser cache.
- **BREAKING: `deferred` is now a closed status.** Setting work aside is a way of closing it, not a state of being open. `deferred` nibs are excluded from `--open` and `--ready`, included in `-s closed`, and hidden by the web's "Open" preset. A `deferred` blocker still blocks the work that depends on it — unlike `completed`/`scrapped`, the set-aside work is coming back, so the dependency is unmet. **No data migration:** `status: deferred` stays valid in front matter and no file is rewritten.
- **BREAKING: `nibs set -s <a closed status>` is refused**, and the error names the `close` command to run instead. `close` requires a summary and `set` does not, so allowing both made the route that records nothing the shorter one. This governs the `set` verb, not the data — the web UI, TUI, `nibs graphql` and `nibs new -s <closed>` can still reach a closed status directly. Only the move *into* closed is refused; `nibs set <id> -s todo` on a closed nib is still how work comes back.
- **BREAKING: the projected `ready` field now requires a startable status.** It previously meant "not closed and unblocked", so draft and in-progress nibs reported `ready: true` while `nibs list --ready` withheld them — 67 versus 38 on the sample fixture. Both now derive from one `Startable` flag (true for `todo` alone) and answer identically.
- **BREAKING: `nibs plan --open` now selects the open status group**, the same set `list`'s and `rel`'s `--open` select, rather than "everything not closed". The two differ only on a nib whose front matter has no `status:`, which is in neither group and is no longer returned.
- **BREAKING: the paired presence filters collapsed to one field each.** The GraphQL `noParent`, `noBlocking` and `noBlockedBy` filter inputs are retired; `hasParent`, `hasBlocking` and `hasBlockedBy` are tri-state and express all of it. The `--no-parent` and `--no-blocking` CLI flags are unchanged.
- **BREAKING (web):** the `TERMINAL_STATUSES` constant is now `CLOSED_STATUSES` and includes `deferred`, and the Status facet's two presets collapse into a single **Open** — with `deferred` closed, "Open" and "Open + deferred" named the same set. All six statuses remain individually selectable.
- Closing a child now propagates to its parent **by reason**: `## Key Decisions` merge upward for every close reason, but only a `completed` close rewrites the parent's `## Current Focus`. Setting work aside is not progress, and overwriting that section would erase the record of the last real progress. A revision does not retract an earlier `completed` close's parent line — correct it by hand with `nibs body <parent> --section "## Current Focus" --set -`.
- `nibs archive` now moves `deferred` nibs too — it archives every nib in a closed status, and `deferred` is one. Archived nibs remain visible in all queries, as before.
- **BREAKING: a filter naming a nib that does not exist is now refused instead of answered with an empty list.** `nibs list --parent <unknown-id>` exits 3 with `no nib with id "…"` rather than printing zero nibs, and the equivalent GraphQL query returns an error rather than `[]`. This closes a failure mode that mattered most to agents: "what is under nibs-abc1?" answered with an empty list reads as a fact about the store, so a mistyped id was indistinguishable from the truth. All eight id-valued filter fields behave this way and say so in the schema. A target that exists and simply matches nothing is unchanged — still an empty result, still exit 0. A target that resolves and then cannot be read (a concurrent delete) reports a distinct error, so a transient failure is not reported as a typo.

- **Every input to the release job is now pinned.** `go-licenses` was installed with `go install …@latest` and GoReleaser floated across the whole `v2` line, so an arbitrary upstream release could run as code in a job holding `contents: write` — the job that publishes the binaries `install.sh`, `install.ps1` and `nibs upgrade` consume. Both are pinned in `mise.toml` (`goreleaser = "2.17.1"`, `go-licenses = "1.6.0"`), every `uses:` reference is a full commit SHA rather than a movable tag, and `goreleaser-action` is gone — GoReleaser runs as the pinned binary, one less third-party action inside that job. `task licenses` and the local dry-run in `RELEASING.md` use the same pinned versions the release job does.
- **CI installs its tools from `mise.toml` instead of restating their versions.** Both workflows now provision go, node, task and golangci-lint with `jdx/mise-action`, so `mise.toml` is the single place any of those versions appears — nine hand-typed copies across `ci.yml` and `release.yml` previously had to be bumped together, with nothing cross-checking them. The lint job runs `task lint`, reaching the linter through `mise exec` exactly as a local run does.

### Removed
- **BREAKING: the `parked` status group** (`-s parked`, `--no-status parked`). It was a one-member group and a spelling variant of `-s deferred`; use `-s deferred`, or `-s closed` for every closed status.
- **BREAKING: the `--active` flag** on `list` and `rel`. `--open` remains, and `-s in-progress` covers the other reading. With `open` meaning draft/todo/in-progress, "active" was wrong in both directions.

### Fixed
- **A refused `updateNib` no longer leaves durable edits on other nibs.** The mutation wrote to *other* nibs' files before validating its own subject, so a mutation reported as failed could still have committed real changes elsewhere — an `addBlocking` target gaining a `blocked_by` entry and a moved `updated_at`, or a sibling silently gaining a backfilled `order:` key. The subject's write-free guards (enum validity, an `ifMatch` required by config but missing, and an `ifMatch` that disagrees with what is on disk) now run ahead of every step that can touch another nib, so a refusal on any of them writes nothing. A residual window remains, and the mutation's own schema description states it: a concurrent write, a flock failure, a concurrent delete, or write I/O can still refuse the subject after other nibs are written — the same window the bulk reorders already document.
- **`nibs query` now reports the `occurrences` count when a surgical replace is refused.** A batched `bodyMod.replace` whose search text matched zero times, or more than once, reported a bare `VALIDATION_ERROR` with no count — losing the field that separates "your text was not there" from "your text was ambiguous", two refusals with different repairs. It now reports `TEXT_NOT_FOUND` or `TEXT_AMBIGUOUS` with the count in the `--json` envelope, matching what `nibs body --replace-old` already did; both surfaces classify through one shared path, so they cannot disagree about the same refusal. A zero-match emits a real `occurrences: 0` rather than omitting the field. Where several failures share an exit status but differ in kind, the response still generalizes to `VALIDATION_ERROR` and withholds the count, since no single count would speak for it.
- **`nibs check --fix` deleted valid links whose target file merely failed to parse.** In one run it would print `Cannot auto-fix unparseable nib file X (repair it by hand)` and, in the very next line, `removed broken link parent:X` — erasing an edge that repairing the file would *not* have brought back. A skipped file's id never enters the store, so every link naming it looks broken; `--fix` now recognizes that such a target is unresolvable-for-now rather than missing, keeps the link, and says so. Genuinely dangling links are still removed.
- **A running `nibs serve` and a fresh `nibs list` could disagree about the same link, permanently.** Canonicalization rewrote a nib's stored link spelling and discarded the file's, so the next re-resolution read its own previous output instead of the file. Restoring a deleted nib then left the live store answering `nibs-e1` while a fresh load answered `e1`, for the same directory, indefinitely — and the next unrelated write to the affected nib would persist the live answer. Link resolution now always reads the spelling in the file, which also makes repeated sweeps idempotent and reversible, and closes the matching gap where creating a nib did not re-resolve links that had been waiting for that id to exist.
- **`task lint` could not catch a formatting violation, and 53 files were unformatted.** The repo had no `.golangci.yml` at all, so golangci-lint ran on its defaults — which enable no formatter — and reported `0 issues.` on a tree where `gofmt -l` listed 53 files across `cmd/`, `internal/tui/`, `internal/nibcore/`, `internal/graph/` and more. Drift accumulated behind a green gate with a reviewer's eye as the only thing standing in: one recent changeset added a struct field to a test table without re-running gofmt, misaligning five field names, and three reviewers caught by hand what the gate could not. The repo now carries a `.golangci.yml` enabling the `gofmt` formatter, and the backlog is cleared in one mechanical commit so the gate applies to all code rather than only to newly-touched code. gofmt was chosen over goimports — measured byte-identical on this tree, since every import block is already grouped std-then-third-party — and over gofumpt, which would have cost 84 files rather than 53 for opinions beyond the standard. Note that gofmt already sorts imports *within* a group, so an unsorted third-party block is a plain gofmt violation and needs no import-specific linter. The default `standard` linter set is unchanged; this config only adds the formatter.
- **`scripts/go-test-capped.sh` warned and then ran the very thing it exists to prevent.** Where a memory-capped systemd scope was unavailable it printed a warning to stderr and executed an uncapped `go test` anyway — so the protection against a runaway test taking down the whole WSL VM was absent exactly when the environment was unusual enough to need it, announced only by a line that scrolls past in `task test` output. On WSL the script now refuses, with a non-zero exit and a message naming the `GO_TEST_UNCAPPED=1` override. Off WSL it is simply a plain `go test`: a runaway there is an ordinary process-level OOM that kills the test binary and fails the run, which is the correct outcome and never needed a guard.
- **A flaky watcher test intermittently blocked CI, and with it releases.** `TestRapidUpdatesToSameFile` failed in the `-race` lane with `expected title 'Update 5', got ""`, which is enough to stop a release: `release.yml` gates on the CI run's conclusion for the release commit, so a red race lane means nobody can cut a release until someone notices and re-runs. Two test defects, neither in the product. The watcher tests wrote nib files with `os.WriteFile`, which truncates before it writes; fsnotify reports the truncate, so a debounce batch firing inside that window loaded a nib parsed from bytes that did not carry the title yet. And the test asserted on whichever batch arrived first, though nothing pins which debounce window each write falls into — a runner that stalls the test goroutine past the debounce delay legitimately publishes an intermediate value first. Test writes now go through the same temp-file-plus-rename path production uses, at every site that writes a `.md` file while a watcher is live, and the test waits for the settled value instead of judging the first batch. Production was never exposed: `saveToDisk` has always written atomically, and a torn read from an external non-atomic writer self-heals on the next event.
- **`task test` and `task build` failed intermittently in the dependency install step**, and the failures read as something else entirely. Every invocation ran `npm ci`, which either aborted with `ENOTEMPTY` while deleting `node_modules` — leaving a half-deleted tree that surfaced as thousands of phantom type errors in untouched files — or reported success while leaving `node_modules/.bin` empty, which showed up much later as `vite: not found`. Dependencies are now installed only when `package-lock.json` actually changed or the tree is broken, so the fragile step is no longer on the path of every build and test run, and a tree npm left half-linked repairs itself instead of failing in an unrelated step. Note that two `task` runs must not install at the same time — a lock was implemented for this and removed once measurement showed `mkdir` is not atomic under the `uutils` coreutils this project runs on, and a lock that silently fails to exclude is worse than none.
- **The font-size preference did not reach the filter box, buttons or dropdown menus.** Small/Medium/Large moved the table and detail text but left those controls pinned at one size — at Large the filter box read noticeably smaller than everything around it. Tailwind's own size scale is now driven by the same multiplier, so the whole UI moves together. Two controls that a token could not reach are fixed alongside it: the small button size, whose fixed value had made it *larger* than a default button at the Small setting, and the dropdown width cap, which previously clipped long labels at Large that fit at Medium.
- **Typing `word:` in the filter box flashed a query-syntax error into the list.** A half-typed token reached the search backend as a malformed query; the list refetch is now debounced and the partial token no longer escapes.
- **A filter combining several hierarchy predicates could match nothing and say only "No nibs found".** Two picks from "Filter related" can compose a filter no nib satisfies — nothing lies strictly between a direct parent and its child, for instance. The empty state now names the active tree relationships and offers to clear them.
- **Recognized relationship tokens rendered as muted free text**, so `ancestor:<id>` looked like stray text the parser had ignored even though it was filtering. The highlighter now routes through the same recognizer the parser uses, so the two cannot disagree.
- **`constructor:` and `__proto__:` parsed as real relationship tokens**, and a bare `constructor` was silently dropped from full-text search, because the token lookups inherited members from `Object.prototype`.
- The filter autocomplete and the invalid-token marker rendered behind the sticky table header and the table rows.
- The token hover control overlapped its token's own last character, so `type:bug` could read as `type:b×g`; removal is click-to-select plus <kbd>Delete</kbd>.
- **On Windows, the TUI and the web UI did not pick up external nib changes.** Editing a nib from a second shell (`nibs set <id> -p high`) changed the file on disk while an open TUI kept showing the old value. Every nib write commits as a rename over the existing file, and Windows reports that replacing rename on the target as a remove immediately followed by a create; both halves collapsed into one debounce batch, and the watcher read the remove bit as "the file is gone", checked that it was in fact still there, and then discarded the whole batch instead of reloading it. A removal is now only treated as one when nothing remains at that path, so the edit falls through to the reload it always needed. Both surfaces share the watcher, so both were affected and both are fixed.
- **`nibs check --fix` deleted valid links.** A `blocked_by` or `parent` entry written in short form (`e001` rather than `nibs-e001`) was reported as a broken link and removed from the file on disk, after which the nib was handed out as ready work. Such links now resolve the same way everywhere, and a short-form self-reference is reported as a self link rather than a broken one.
- **A link written in short form was only half traversable.** `parent: par` in a hand-edited file answered when followed from the nib holding it, but the nib it named listed no such child — and the same asymmetry hid a `blocked_by` edge from `--rel blocking` and made a short-form parent cycle invisible to `nibs check`, which reported no issues while the forward resolver looped through it. Link ids are now resolved to their full form once, when a nib is read from disk, so both directions and cycle detection agree. An id that names no nib cannot be resolved and is left exactly as written, so `check` still reports it broken against the spelling in the file. **Files are not rewritten:** the resolution is in-memory only, but the store now holds the full form, so the next ordinary write to such a nib (`set`, `body`, `close`) persists it — a hand-written short id becomes canonical on its next save.
- **`--has-parent=false` and `--has-blocking=false` were silently ignored**, returning the unfiltered set — all 89 nibs on the sample fixture instead of the 24 parentless ones — because the flag's value was tested rather than whether it was given. `--is-blocked=false` had the same defect.
- **Contradictory filter flags returned an empty set with exit 0 and no error.** `--has-parent --no-parent`, `--has-blocking --no-blocking` and `--parent <id> --no-parent` are now validation errors naming both flags.
- **An explicitly empty id filter is no longer ignored.** `--parent ""`, `--mentions ""` and `--mentioned-by ""` returned every nib; they now error. `-S ""` is deliberately still accepted as "no keyword filter".
- The projected `ready` field and `nibs list --ready` disagreed when a nib's `blocked_by` named its blocker by short id — the field withheld it, the filter handed it out.
- Re-closing a nib appended a duplicate copy of its `## Key Decisions` to the parent on every close.
- The `## Summary` date stamp used the machine's local timezone while `updated_at` is UTC, so one close could be recorded under two different dates.
- The duplicate-title warning lost its `reason` for anything closed through `close --as`, because it read only the retired `## Reasons for Scrapping` section. It now reads the most recent `## Summary` entry, falls back to the old section for nibs closed before this change, and explains deferred nibs as well as scrapped ones.
- `nibs list --ready` widened to every unblocked nib, of any status, if no status declared itself startable; that configuration is now a validation error rather than a silently wider answer.
- `nibs catalog`'s `--ready` description no longer disagrees with `nibs list --help`, and the agent guides no longer describe the parent propagation or the closing rules in terms this release makes false.
- **A nib whose `parent:` names a nib that does not exist is now a root everywhere, instead of being a root to some surfaces and parented to others.** The link resolving is what decides parent-ness; a non-empty field that resolves to nothing is not a parent. Previously `hasParent: true` claimed such a nib had a parent while the `parent` field in the very same response was `null`, `nibs list --no-parent` omitted a nib the tree rendered at root level, and `nibs rel <id> --rel siblings` listed it as a root's sibling in one direction but not the other. Reordering was split the same way: a nib offered as a sibling was then refused as that sibling's reorder anchor. All of it — the filters, the `children`/`parent` resolvers, `nibs rel`, `nibs mv`, and bulk reorder — now decides the question one way. This state is reachable only by hand-editing a file or by a merge in `.nibs/`, and `nibs check` still reports the link as broken; the two are complementary, not contradictory.
- **Root-level bulk reorder was impossible in any project holding such a nib.** Listing it was rejected as "not a child" and omitting it was rejected as "missing child", leaving no accepted input. The membership and completeness checks now draw the root set the same way.
- Bulk-reorder errors reported a parent that was not the one compared. The message now names the resolved value, and the stored spelling alongside it when the two differ, so there is something to grep `.nibs/` for.
- **BREAKING: an explicitly empty id-valued filter value is refused instead of being ignored.** `nibs(filter:{parentId:""})` returned the whole store, because every id branch was gated on a non-empty value and an empty one dropped the branch. An empty string is what a client sends when a variable did not interpolate, which is exactly when a silently widened answer does the most damage. All eight id-valued fields now report a validation error (exit 2) and say so in the schema — the same answer `nibs list --parent ""` already gave, so the flag surface and the GraphQL surface agree about one user mistake. `hasParent: false` remains the way to select nibs that have no parent. A whitespace-only value is unchanged: `" "` is an id that resolves to nothing, not an empty one, and is still refused as not-found. An empty `search` is also unchanged — "no keyword filter" is a real meaning, whereas there is no nib whose id is `""`.
- **`nibs query` reports the same exit codes as the direct commands.** Every GraphQL error was flattened to exit 2, so `nibs list --parent <unknown>` exited 3 while the same refusal through `nibs query` exited 2 — and `nibs query` is the surface agents are most likely to script against. Not-found now exits 3, an unreadable target 5, and a stale `if-match` 4 with the server's `currentEtag` in the `--json` envelope, so a conflict through `query` is as reconcilable as through `set`. **BREAKING:** a response whose errors belong to different *exit classes* reports the new `UNCATEGORIZED` code and exits 1 rather than claiming exit 2, which in this CLI means the caller's input was at fault — a claim a mixed batch does not support. Failures that differ in kind but share an exit status keep it, reported under that class's general code. **BREAKING:** `nibs mv <unknown-id>` now exits 3 like every other command, instead of 2.
- **Deleting a bare-token nib no longer silently re-parents nibs whose stored link used the bare spelling.** Link canonicalization was a load-time and watcher-batch invariant rather than a store one, so a store holding both `e1` and its prefixed twin `nibs-e1` kept a raw `parent: e1` in memory; removing `e1` left the store saying one thing while lookups answered another, with no event, no warning and no file change. Removals now re-canonicalize — through `Core.Delete` and through the watcher, which previously swept only on arrivals — and a delete reports each link it re-points.
- **`task lint` runs the golangci-lint version the project pins.** `mise.toml` pinned every tool to `"latest"`, which is resolved separately on each machine and once per CI run, so two checkouts of one commit could be linted by releases that disagreed about this codebase — one reporting six findings the other did not. Exact versions are now pinned and mirrored into both workflows, and the lint task runs the linter through mise so PATH order cannot decide which one lints. It also fails with a message naming the prerequisite instead of an unexplained exit 127, and `CLAUDE.md` and `README.md` no longer imply that installing mise is sufficient — a fresh clone needs `mise trust` and `mise install`, and mise's tools apply only once its shims are reachable.
- **A search result could repeat an ancestor.** When two nibs named the same parent with different spellings of its id, the ancestor-completion step banked the spelling rather than the nib, so it was fetched and added twice and the duplicate reached the client. The three parent-chain walks the codebase had grown are now one, which is what made the divergence visible.
- **BREAKING: a `search` term now filters relationship fields, where it was silently dropped.** `children(filter:{search:"foo"})` returned every child regardless of the term — 209 of them for a term matching nothing — because only the top-level query honored `search`. It now intersects the relation with the matches, so the field means "the children of X matching foo". Ancestor completion is deliberately not carried across: that is top-level tree-building, and a caller asking for children did not ask for their ancestors. The result is bounded by the store-wide search limit, which the schema now states rather than truncating silently.
- **BREAKING: two unsatisfiable filter combinations are refused instead of answered with an empty list.** `parentId` with `hasParent: false`, and `blockedById` with `hasBlockedBy: false`, cannot match anything — and an empty list at exit 0 is indistinguishable from "that parent genuinely has no children". Both now report a validation error, matching what `nibs list --parent X --no-parent` already did. `blockingId` with `hasBlocking: false` is **not** refused: `hasBlocking` means *actively* blocking, so that pair selects the blockers a nib still lists that are no longer blocking anything, which is a real question. In the web UI the refusal routes to the existing "Clear hierarchy filters" button rather than a raw error box — reaching it takes two clicks, not a hand-typed query.
- **BREAKING: a parent cycle renders instead of erasing every nib in it.** Both tree builders treated a nib as a root only when it had no parent, so in a cycle none qualified and the whole cycle vanished — a store holding two nibs rendered nothing. The lowest-id member is now promoted to a root and the rest nest beneath it. A nib the user cannot see is worse than one shown in the wrong place.
- **`deleteNib` deletes and unlinks the same nib.** It resolved its target through a normalizing lookup, then passed the caller's raw spelling on, so `deleteNib(id: "tgt")` removed `nibs-tgt` while stripping zero incoming links — leaving every child and every blocked nib pointing at an id that was gone. Reachable through the GraphQL API, the web and the TUI; `nibs rm` and `nibs delete` were never affected.
- **A failing batch mutation names what it committed.** Root mutation fields run in document order and execution does not stop at the first failure, so a batch could delete two nibs, fail on a third, and report a bare "nib not found" naming neither deletion. The message now carries the outcome — `nib not found; d1, d3 succeeded; d2 failed`. The succeeded list is a lower bound rather than an accounting: a failed `updateNib` persists its blocking targets before its own `ifMatch` guard, so re-read a referenced nib rather than trusting a cached etag.
- **`nibs set --parent` and `nibs query` report an illegal reparent as a hierarchy error**, with the `allowedParentTypes` hint that `nibs mv` and `nibs new` already gave. That hint is what turns a refusal into a next action, and the two surfaces most likely to be scripted were the ones without it. A `--type` change that would orphan a child now names which child.
- **An oversized filter id no longer amplifies the response by the size of the store.** The id was echoed in full in each refusal, and a relationship-field filter refuses once per nib, so a 100 KB id returned an 8.9 MB response on an 89-nib fixture. The echo is capped, with the original length reported; the same query now returns 18 KB — smaller than the request that provoked it.
- **The toolchain has a bump signal.** Pinning exact versions removed the only mechanism that pulled Go security releases into published binaries, and nothing replaced it. Renovate now covers `mise.toml` and both workflows, grouping each tool's mirrored sites into one pull request. Node is pinned alongside the other three, where it had been set in CI and nowhere else. Node majors are held for a deliberate decision rather than arriving automatically.
- **`task go:codegen` refuses to run while a comment directive sits on a resolver's doc comment.** gqlgen rebuilds those comments in a way that discards directives and keeps the prose, so a `//nolint:` or `//go:` directive there would silently stop taking effect at some later commit that happened to regenerate. Directives inside a resolver body survive. The check expires itself: the upstream fix landed in gqlgen v0.17.86, and taking that bump fails the build until the guard and its notes are retired with it.
- **`nibs rel <id>` silently defaulted to `--rel neighbours` without saying so anywhere.** Both places a caller learns the grammar presented `--rel` as required — `nibs cheat` printed it unbracketed beside genuinely optional elements, and `nibs rel --help` documented every other flag's default but not that one. For a root nib the default returns every other root, which is large and looks like a real relationship set, so the failure mode was a plausible wrong answer rather than an error. The default is now stated in the help, the flag usage and the cheat sheet, all read from one constant.
- **The web TypeScript outside `src/` was type-checked by nothing.** `web/tsconfig.json` includes `src/` only, so the Playwright suites (`screenshots/`, `e2e/`) and the top-level vite, vitest, playwright and graphql-codegen configs were seen by no gate at all — `npm run check` never looked at them, and Playwright and Vite strip types to run a file rather than verifying them. The failure that allows: rename a value in `src/`, and every stale use under `src/` is flagged while a stale literal in `capture.spec.ts` still compiles, seeds a value the app no longer recognizes, and surfaces much later as a confusing runtime assertion failure in `task screenshots` — a suite that is not part of `task test`. A second config, `web/tsconfig.tooling.json`, now covers everything outside `src/`, checked by `tsc` through `task web:check-tooling`. It runs from `task web:check`, which is the one task both gates already call: `task test` runs it, and CI's lint job invokes it directly while the test job deliberately does not go through `task test`. Membership is by location rather than by filename, so a tool added later is checked without editing a list. The two configs stay separate rather than one widened `include` because these files run in Node and need its globals, which merged into the app config would put `process` and Node's `setTimeout` return type in scope for browser code. All seven previously-unchecked files pass today — the defect was the absent gate, not a present error.
- **Two controls in the filter band used the browser's native tooltip instead of the app's.** The `?` syntax-help button and the filter-token hit region were the only ones in that row still on a plain `title`, so they hinted with a different delay, a different placement and no theming while every neighbor — New, Group by, Columns, the clear-× — went through the styled path. Both now use it too. The shared wrapper behind those neighbors was named `TooltipDropdownTrigger` and only ever wrapped a tooltip around whatever it was given; it is now `WithTooltip` and documents the two ways a trigger attaches to it. It also absorbs two things that had been the caller's problem: tooltip content is portaled to `<body>`, so a trigger inside an `aria-hidden` subtree needs its content marked hidden too or the hint is announced while the thing it describes is not; and the underlying library merges a `type` attribute in unconditionally, which is invalid anywhere but a `<button>` and cannot be written over on a `<span>`.
- **In the TUI, a nib whose `parent:` names a nib that does not exist could not be reordered, and pressing the key said nothing.** It rendered as a root but the reorder path looked up the parent it names, found nothing, and stopped — indistinguishable from a dropped keypress. Such a nib now moves among the roots it is displayed with, and groups with them in a multi-selection block move.
- **Every refused reorder in the TUI now says why.** Selecting nibs under different parents, selecting rows that are not next to each other, or pressing the key at the top or bottom of a list previously did nothing at all; each now reports its reason in the footer.
- Refusals and failures in the TUI footer no longer render in the same green as a success.

- **Pre-release versions are now marked as pre-releases on GitHub**, so `nibs upgrade` no longer offers them as routine stable upgrades. `nibs upgrade` filters on GitHub's pre-release flag rather than on the tag's semver suffix, and GoReleaser leaves that flag off by default — so a tag like `v0.8.0-alpha.1` would have been published looking like any other release. No published release was ever affected; this was caught by cutting the first pre-release.

### Security
- **The release signing key is no longer exposed to third-party build scripts.** GoReleaser's `before` hooks inherit the environment of the release step, so the hook running `npm ci` — which executes install scripts for every package in the web dependency tree — ran with the signing key readable in its environment. The hooks are gone; the same work runs as `task release:prep` before the key is in scope, so the key-bearing step has no third-party children. No key was ever used in a published release.
- **A release now fails if the signing key is not one binaries trust.** Signing with a key whose public half is not embedded produces a valid-looking signature that no nibs binary can verify, which would strand every install once signature verification is required. The release job now checks key correspondence before tagging or publishing, and re-verifies the published signature afterwards.
- **BREAKING: `nibs upgrade` now requires releases to be signed.** It verifies `checksums.txt` against an Ed25519 key compiled into the binary, then verifies the downloaded archive against that checksums file — so a release can no longer vouch for itself. Because the signature is fetched during release *detection*, an unsigned release is not seen at all rather than merely rejected: `nibs upgrade --version <tag>` cannot reach any release predating signing, and every future release must be signed. The release workflow enforces that from the other side — it fails before tagging if the signing key is not one binaries trust, and re-verifies the published signature before finishing. Upgrading *to* the first signed release is unaffected: older versions check `checksums.txt` as they always did.
- **Releases now publish `checksums.txt.sig`**, a detached Ed25519 signature over the checksum file, produced from a key held in a protected `release` environment. `checksums.txt` on its own ships in the same release as the archives it vouches for, so it detects corruption in transit but not anyone able to write that release; the signing key is not in the release, so a signature is an anchor the release cannot forge. Three public keys are compiled into every binary so the signing key can be rotated later without stranding installs — a binary can only verify against keys it already carries, so that headroom had to be bought up front. **`nibs upgrade` does not require the signature yet**; it is being published first so that no binary depends on it before a real release has produced one.
- **CI now fails on a dependency with a known vulnerability.** `task vulncheck` runs `govulncheck` in the lint job and on a weekly schedule, gated by an explicit allowlist in `scripts/vulncheck-allow.txt`. Nothing previously scanned dependencies at all — Renovate watches *versions*, not advisories, so a vulnerability published against an unchanged dependency produced no signal. The gate fails in both directions: on a finding nobody has reviewed, and on an allowlist entry that no longer matches anything, so a suppression cannot outlive the reason it was added. One advisory is currently allowlisted, [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932), which has no fixed version.
- **Release assets now carry a build provenance attestation.** Every published archive and `checksums.txt` gets a signed statement that those exact bytes were built by this repository's release workflow at a specific commit, verifiable with `gh attestation verify nibs_linux_amd64.tar.gz --repo alphaleonis/nibs`. It is anchored in Sigstore and GitHub's OIDC identity rather than a key the project holds, so there is no public key to distribute and nothing to rotate. `checksums.txt` alone could not make this claim: it ships in the same release as the archives it covers, so it catches corruption in transit but not anyone able to write that release. `nibs upgrade` does not consume the attestation yet — it still verifies `checksums.txt` — so this covers manual downloads and `install.sh`.
- **Two vulnerable dependencies reachable from nibs' own code were updated.** goldmark `1.7.13` → `1.7.17` closes a cross-site scripting issue ([GO-2026-5320](https://pkg.go.dev/vuln/GO-2026-5320)) reachable from mention extraction, which matters because nibs renders that Markdown into the web UI; `golang.org/x/text` `0.38.0` → `0.39.0` closes an infinite loop on invalid UTF-8 ([GO-2026-5970](https://pkg.go.dev/vuln/GO-2026-5970)) reachable from GraphQL enum marshaling. Both were found by `govulncheck`, which reports reachability rather than version matches; it now reports one remaining advisory, [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932), for which no fixed version exists.

## v0.2.0 - 2026-04-11

### Added
- `nibs config set-prefix <new-prefix>` — new CLI command to change a project's nib ID prefix. Renames every nib file (active + archive), rewrites `parent` and `blocked_by` front-matter references, and atomically updates `.nibs.yml`. Supports `--dry-run` to preview the plan, `--force` to override the git-dirty guard, and `--json` for structured output.
- Install scripts for Linux, macOS, and Windows (`install.sh` / `install.ps1`) invoked via `curl | sh` or `irm | iex` from the README.

### Fixed
- `install.ps1` now works under PowerShell Core (`pwsh`): uses the .NET `System.IO.Compression.ZipFile` API directly to avoid cmdlet shadowing issues that broke `Expand-Archive` in some environments.

### Changed
- Build and dev task runner migrated from mise's `[tasks]` to [go-task](https://taskfile.dev/) (`Taskfile.yml`). mise still manages tool version pinning (Go, golangci-lint, Task itself). Contributors building from source should run `mise install` to pull the pinned tools, then `task build` / `task test` / `task lint`. Runtime and CLI behavior are unchanged.
