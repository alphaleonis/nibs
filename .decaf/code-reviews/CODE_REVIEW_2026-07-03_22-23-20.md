### #1 🟠 High: `ensureVisible` effect self-invalidates (`effect_update_depth_exceeded`) on Back/Forward/deep-link to a nib excluded by an active filter

| | |
|---|---|
| **File** | `web/src/lib/components/TreeTable.svelte:146-187` (effect), triggered by `web/src/lib/composables/useHistoryNav.ts:50-69` |
| **Category** | reactivity / resource-management |
| **Confidence** | 75 — **validated: CONFIRMED** |
| **Found by** | adversarial-reviewer (High); confirmed by finding-validator + orchestrator code analysis |
| **Pre-existing** | effect predates the diff but was **latent** — the only prior `ensureVisible` caller (post-drag, App.svelte:106) is gated off by `isDragAllowed` (filter.ts) whenever a client filter is active; this change makes it reachable with arbitrary user-navigated ids |

**Issue:** The new `handlePopState`/`syncFromUrl` call `selection.ensureVisible(id)` with any URL/history-derived id. When an advanced/client filter is active, `buildTableData` (`web/src/lib/tableData.ts:84` — `if (visibleIds && !visibleIds.has(node.nib.id)) continue;`) drops any nib that neither matches the filter nor is an ancestor of a match from `rows`, while it stays in `allNibs`. For such a nib X, the ensure-visible `$effect`:
- does **not** bail at line 157 (`nibMap.has(X)` is true — X ∈ `allNibs`),
- enters the expand-ancestors branch at 163 (`!visibleRowIds.includes(X)` is true),
- assigns `collapsedIds = next` (line 172) — a brand-new `Set` reference — and returns **without** clearing `pendingEnsureVisibleId`.

Because `collapsedIds` is `$state` (line 134) and the effect reads it, the reassignment re-runs the effect; but expanding ancestors can never bring X into `visibleRowIds` (the filter excludes it regardless of collapse state), so the branch repeats forever, each pass minting a new `Set`. Svelte 5 throws `effect_update_depth_exceeded` (or the UI churns), breaking the app after an ordinary Back/Forward or reload to a filtered-out nib.

**Fix:** In the expand branch, clear `pendingEnsureVisibleId` when expansion cannot make the target visible (target ∈ `nibMap` but ∉ `visibleIds`/filtered out), and/or only reassign `collapsedIds` when the new set actually differs from the old, so the effect terminates.

### #2 🟠 High: Selection-mutation paths bypass `nav`, desyncing browser history/URL from the visible panel

| | |
|---|---|
| **File** | `web/src/lib/composables/useKeyboardShortcuts.svelte.ts:85`; `web/src/App.svelte:118`; `web/src/lib/components/RowContextMenu.svelte:54`; `web/src/lib/composables/useEditorOrchestration.svelte.ts:129` |
| **Category** | logic / state-desync |
| **Confidence** | 100 — corroborated ×5 (validation waived) |
| **Found by** | quick (High), broad (High), consistency (High), design (High), adversarial (High) |
| **Pre-existing** | call sites predate the diff, but this change establishes `nav` as the canonical funnel and leaves these unrouted — the inconsistency is introduced here |

**Issue:** `navigateToNib`/`closePanel` only push a history entry when *they* change `selection.selectedNibId`. These paths mutate selection directly, so the URL (`?nib=`) and history stack silently diverge from what the panel shows:

- **Escape** (`useKeyboardShortcuts.svelte.ts:85`) calls `selection.close()` → panel closes but URL stays `?nib=A`; a later `nav.navigateToNib("B")` pushes on top of the stale `A` entry, so Back skips the step the user actually experienced, and refresh/share of that URL reopens A.
- **Right-click auto-select** (`App.svelte:118` `handleRowContextMenu`) and **context-menu "Open"** (`RowContextMenu.svelte:54`) call `selection.select()` — panel changes with no history entry.
- **Editor save** (`useEditorOrchestration.svelte.ts:129`) selects the new/edited nib (e.g. after "Add child") without a push.

This also disables the idempotence guard's ability to self-correct: once selection drifts to X via a bypass path (history top still `{nibId:A}`), an explicit click on X's title early-returns at `useHistoryNav.ts:39` (`selectedNibId === X`) and never pushes `{nibId:X}`, permanently locking the URL to A; conversely a plain click after a bypass-`close()` can push a duplicate consecutive entry (Back appears to do nothing).

**Fix:** Route the genuine-navigation call sites through the `HistoryNav` contract — `nav.closePanel()` for Escape, `nav.navigateToNib(id)` for right-click auto-select, context-menu Open, and editor-save (inject `nav` via `opts` where `selection` is already injected). Confirm intent for editor-save (a new-nib auto-select may or may not warrant a Back-stop) and document it if excluded. Routing all panel-opening/closing transitions through `nav` also makes the `selectedNibId === id` guard sound (see #6).

### #3 🟠 High: Cold-load deep-link (`/?nib=<id>`) loses ancestor-expand / scroll-into-view

| | |
|---|---|
| **File** | `web/src/lib/composables/useHistoryNav.ts:60-69` (`syncFromUrl`); `web/src/lib/components/TreeTable.svelte:156-160` |
| **Category** | race-condition |
| **Confidence** | 75 — corroborated ×4 + orchestrator code-verified (validation waived) |
| **Found by** | quick (High), broad (Medium), design (Medium), spec-compliance (Medium, AC3) |
| **Pre-existing** | the raced effect predates the diff; this change adds the first caller (`syncFromUrl` on mount) that runs before tree data has loaded |

**Issue:** App.svelte's mount `$effect` calls `nav.syncFromUrl()` synchronously, before `TreeTable`'s GraphQL query resolves (`allNibs` is `[]` on first render). `syncFromUrl` calls `selection.ensureVisible(id)`; the ensure-visible effect then hits the "not in dataset" branch (`!nibMap.has(nibId)` at 157) and calls `clearEnsureVisible()`, dropping `pendingEnsureVisibleId` **before** data arrives. When the query later populates, the effect re-runs but `pendingEnsureVisibleId` is already `null`, so the expand/scroll never happens. Net: a shared/bookmarked `/?nib=<nested-id>` selects the nib and opens the panel, but the tree neither expands its collapsed ancestors nor scrolls it into view (defeats nibs-58c3 AC3). The panel *does* open (a separate reactive effect at App.svelte:198-209 handles pane expansion), so this degrades gracefully. **Severity dissent:** quick rated High; broad/design/spec rated Medium given the graceful degradation.

**Fix:** Distinguish "dataset not yet loaded" from "nib absent" — only `clearEnsureVisible()` once the query has settled (guard on fetch state), or re-issue `ensureVisible` when the first query result arrives if the selected nib isn't yet visible. Note the fix must not reintroduce #1 (clear when genuinely absent/filtered-out).

### #4 🟡 Medium: `isNibState` type guard checks only the key, not the value type

| | |
|---|---|
| **File** | `web/src/lib/composables/useHistoryNav.ts:22-24` |
| **Category** | type-safety / runtime boundary |
| **Confidence** | 75 |
| **Found by** | typescript (Medium), test (coverage of the false branch), design (folded) |

**Issue:** `return !!state && typeof state === "object" && "nibId" in state;` narrows to `{ nibId: string | null }` but only asserts the key exists. `history.state` is external, persisted data (survives reload/redeploy, writable by any script on the origin). A `{ nibId: 42 }` passes the guard and a non-string flows into `selection.select(id)`; `{ nibId: "" }` passes then `if (id)` treats it as falsy and *closes* instead of selecting. Low practical impact today (this module is the only writer), but the guard is unsound for what it asserts.

**Fix:** Also validate the value type: `... && "nibId" in state && (typeof (state as {nibId: unknown}).nibId === "string" || (state as {nibId: unknown}).nibId === null)`.

### #6 🟡 Medium: Undocumented decision — intentional `nav` bypasses (multi-select) are indistinguishable from bugs; guard invariant unstated

| | |
|---|---|
| **File** | `web/src/lib/components/TreeTable.svelte:312-318`; `web/src/lib/composables/useHistoryNav.ts:39,45` |
| **Category** | knowledge / decision-missing |
| **Confidence** | 75 |
| **Found by** | knowledge (conf 75), broad (Medium), design (folded) |

**Issue:** Ctrl/Cmd+click (`toggleSelect`) and Shift+click (`rangeSelect`) can collapse to a single `selectedNibId` (opening the panel) or clear it — without a history push, exactly like the bypass bugs in #2 — but here it is a *defensible* scope decision (multi-select is a bulk gesture, not navigation; spec-compliance agrees). Nothing in the code marks it intentional, so a maintainer cannot tell it apart from the #2 omissions. Likewise the idempotence guards (`selectedNibId === id` / `=== null`) silently encode "selection only moves through nav," an invariant several live paths violate.

**Fix:** Add a one-line comment at the multi-select branch ("bulk-selection gesture — intentionally not routed through nav, no Back/Forward entry") and at the guards ("assumes detail-panel navigation flows only through nav; multi-select, context-menu, and Escape mutate selection without recording history"). Cite nibs-58c3.

### #8 🟢 Low: URL write path is not param-preserving / read-write asymmetric (blocks the planned filter-in-URL extension)

| | |
|---|---|
| **File** | `web/src/lib/composables/useHistoryNav.ts:35-36, 60-69` |
| **Category** | evolution |
| **Confidence** | 75 (promoted on 3-agent agreement) |
| **Found by** | design (Medium), broad (Low), knowledge (sole-owner assumption) |

**Issue:** `nibIdFromSearch` reads via `URLSearchParams` (param-aware, tolerates `?a=1&nib=y`), but `nibUrl` rebuilds the query as the literal `?nib=<id>` and `closeUrl` returns bare pathname — so every navigate/close/sync discards any other query param. Inert today (filters live in localStorage), but nibs-58c3 explicitly plans filter/view-in-URL as a follow-up; that extension will silently clobber params on every nib navigation, and `isNibState` implicitly assumes `nav` is the *only* `history.state` writer.

**Fix (forward-looking):** Build URLs by mutating the current `URLSearchParams` (set/delete `nib`, preserve the rest), symmetric with the reader; document the single-writer assumption on `isNibState`.

### Considered But Not Flagged (all agents)

- **Mount-time `onCollapse` closes the deep-linked nib** — **refuted by validator**. Empirical instrumentation showed paneforge's `onCollapse` fires on mount (`paneforge.svelte.js:629` `onMount(registerPane)` → `callPaneCallbacks`, `helpers.js:70-96`) *before* App's parent `$effect` runs `syncFromUrl`, so the `if (selection.panelOpen)` guard reads `false` → `requestAnimationFrame(closePanel)` is never scheduled (zero `pushState` calls across a full flush + 2 rAF frames + 50ms). The pane opens via the separate reactive effect at `App.svelte:198-209`. Refuted.
- **Mount `$effect` runs exactly once** — verified sound by broad, design, typescript, knowledge: `syncFromUrl`/`handlePopState` only *write* reactive `$state` (never read it) and read only non-reactive `window.location`/`history`, so the effect has no tracked deps. (The comment's *attribution* is still off — see Minor/Consistency.)
- **`handlePopState(e:{state:unknown})` vs DOM `PopStateEvent`** — sound: `PopStateEvent` is structurally assignable to `{state:unknown}`; narrowing keeps the composable testable. Verified via `tsc`/`svelte-check` (zero new errors).
- **`nav.handlePopState` listener identity for add/removeEventListener** — stable: `nav` is created once outside the effect; `handlePopState` is a fixed closure property, so cleanup removes the right listener. No leak.
- **`onCollapse` rAF double-push loop (popstate path)** — guarded by `if (selection.panelOpen)` (false by the time it runs); pre-existing rAF pattern. No re-entrancy.
- **`encodeURIComponent`/`URLSearchParams` round-trip** — correct for ids this code produces; real nib IDs are lowercase base36 + prefix (`internal/nib/id.go`), so no reserved chars in practice.
- **`isNibState` empty-string `{nibId:""}`** — folded into #4 (same root cause).
- **Inline `HistoryNav` stub in `makeTestContext`** — structural drift compiler-guarded by `satisfies HistoryNav`; only behavioral fidelity (no guard/ensureVisible) can drift, a test-fidelity concern, not a production gap.
- **`?nib=` scheme / path-stays-`/` rationale not near code** — not flagged: `cmd/spa.go:36-38` already serves an SPA fallback, so a future scheme change wouldn't break refresh/deep-link; rationale lives in the nib.
